# チャット機能のための API 追加・変更の依頼

フロント（moe3-front-rr）で、チャンネル一覧とチャンネル画面を表示だけ先に作った。
発言の送信・発言者の表示・リアルタイム更新に必要な API の追加と変更を依頼する。

項目ごとに「必須」「任意」を付けた。エンドポイント名やフィールド名は案なので、サーバー側の命名規則に合わせて変えてよい。

---

## 前提（フロント側で決まっている仕様）

### チャンネル

チャンネルはサーバーにまだ無いので、フロントは `GET /games/:game_uuid/logs/:season` の結果を次のように振り分けている。

| チャンネル         | 含めるメッセージ             | フロントの channelId                                                  |
| ------------------ | ---------------------------- | --------------------------------------------------------------------- |
| オープンチャンネル | `public` と `system`         | `open`                                                                |
| 独り言             | `personal`（送信者の国だけ） | 国コード 1 文字（例 `f`）                                             |
| 密談               | `confidential` / `masked`    | sender と recipients の国コードを国の並び順でつないだもの（例 `efg`） |

- `ghost` はフロントでは使わない（API 側は今のままでよい）。
- チャンネルは「その組み合わせで初めて発言したときにできる」扱い。今のところ、チャンネルそのものを作る API は要らない（下の「将来」を参照）。

### 誰が何を見られるか

- **参加者**：オープンチャンネル、自分の独り言、自国が入っている密談だけ見える。今の logs API の公開範囲のままでよい。
- **第三者**：第三者用ログビューアーで見る（レイアウトは検討中）。今の logs API の公開範囲（密談は `masked`）のままでよい。
- **管理者**：参加者でなければ、管理者モードの ON/OFF にかかわらず第三者と同じに見える。独り言や密談は、`X-Impersonate-User-Name` で関わっているアカウントに視点変更して見る。**管理者に特別な閲覧権限は要らない。**
  - 第三者と違うのは、管理者モード中にオープンチャンネルへ「管理人発言」を書き込めることだけ（下の 1 と 3）。
  - 管理者モードはフロントのセッションにだけある状態で、サーバーは知らない。
- 終わった卓（Closed・Aborted）は、誰が見ても第三者用ログビューアーで見る。公開範囲は今の「`in_progress` 以外は全員が全メッセージを取得できる」のままでよい。

## 1. 発言の投稿 API【必須】

### エンドポイント（案）

- `POST /games/:game_uuid/messages`

### リクエスト（案）

```json
{
  "kind": "confidential",
  "recipients": ["e", "g"],
  "context": "ベルギーは譲ってほしい。",
  "as_admin": false
}
```

| フィールド   | 型                 | 説明                                                                                  |
| ------------ | ------------------ | ------------------------------------------------------------------------------------- |
| `kind`       | `string`           | `"public"` / `"confidential"` / `"personal"`                                          |
| `recipients` | `string[] \| null` | `confidential` のときだけ必須。宛先の国コード（自国を含めない、重複なし、1 か国以上） |
| `context`    | `string`           | 本文（空文字は不可。上限の文字数はサーバー側で決めてほしい）                          |
| `as_admin`   | `boolean`          | 省略時 `false`。`true` なら管理人発言（下記）                                         |

### 送信者と権限

- 通常の発言は、リクエストしたユーザー（視点変更中は切り替え先のユーザー）の発言として記録する。
  - 担当国があるシーズンは、担当国の発言。
  - 開戦前夜と感想戦は、担当国でなくユーザーの発言（2 を参照）。
- 参加者でないユーザーが通常の発言をしようとしたら 403。
- Closed・Aborted の卓への投稿は 403。感想戦（Finished / Solo / Draw の間）は投稿できる（誰が書けるかは「相談したいこと」の 1）。
- 発言は現在のシーズンに属するものとして記録する（過去のシーズンには投稿できない）。

### 管理人発言（`as_admin: true`）

- `is_admin` のユーザー本人だけが使える。`X-Impersonate-User-Name` 付きのリクエストでは使えない（400 か 403）。
- `kind` は `"public"` だけ（オープンチャンネルにだけ書ける）。それ以外は 400。
- 管理人が卓に参加していても、`as_admin: true` なら担当国ではなく管理人の発言として記録する。
- 管理人発言は、logs API で全員（第三者を含む）に見える。

### レスポンス（案）

- `201 Created` で、作成したメッセージを logs API と同じ形で返す。

### エラー（案）

| Status | code（案）                    | 説明                                    |
| ------ | ----------------------------- | --------------------------------------- |
| 400    | `invalid_kind`                | kind が不正                             |
| 400    | `invalid_recipients`          | recipients が不正（自国を含む・空など） |
| 400    | `empty_context`               | 本文が空                                |
| 403    | `not_a_player`                | 参加者でない                            |
| 403    | `admin_post_not_allowed`      | 管理人発言の条件を満たさない            |
| 403    | `game_not_accepting_messages` | Closed・Aborted など、投稿できない状態  |
| 404    | `not_found`                   | 卓が無い                                |

## 2. 発言者の情報を logs API で返す【必須】

今の `sender` は国コード（`Option<Power>`）だけなので、次の発言者を表せない。

- 開戦前夜・感想戦の発言（担当国が無い、または国でなくユーザーとして表示したい）
- 管理人発言

フロントでは、開戦前夜と感想戦は発言者の Discord アバターと表示名を、それ以外のシーズンは担当国の画像と国名を出す。管理人発言は管理人の画像を出す。

### 変更案（既存フィールドは変えず、追加だけ）

```json
{
  "message_uuid": "…",
  "sender": null,
  "sender_kind": "user",
  "sender_user": {
    "username": "asagix",
    "global_name": "あさぎ",
    "avatar_url": "https://cdn.discordapp.com/…"
  },
  "turn": "ready",
  "context": "よろしくお願いします。",
  "kind": "public",
  "recipients": null,
  "created_at": "2026-11-24 09:00"
}
```

| フィールド    | 型               | 説明                                                                                               |
| ------------- | ---------------- | -------------------------------------------------------------------------------------------------- |
| `sender_kind` | `string`         | `"power"`（国の発言）/ `"user"`（国を持たないユーザーの発言）/ `"admin"`（管理人発言）/ `"system"` |
| `sender_user` | `object \| null` | `sender_kind` が `"user"` のときの発言者。`username` / `global_name` / `avatar_url`                |

- **Discord の数値 ID（discord_user_id）は含めないこと。** フロントでは画面に出さない方針。
- `sender_kind` が `"power"` のときは `sender_user` は `null` でよい。国と人の対応は `GET /games/:game_uuid` の `players[].power` から取れるので、フロント側で引く。
- 開戦前夜・感想戦で発言できるのは誰か（参加者だけか、感想戦は第三者も書けるか）もあわせて決めてほしい（下の「相談したいこと」を参照）。

## 3. リアルタイム配信（SSE）【必須】

チャンネル画面では、新しい発言を SSE で受け取ってすぐに反映したい。

### エンドポイント（案）

- `GET /games/:game_uuid/messages/stream`（`Content-Type: text/event-stream`）

### 要件

- 送るメッセージの形と公開範囲は logs API と同じにする。受け取る人ごとに絞ること（ほかの国同士の密談は `masked`、他人の独り言は送らない、など）。
- 認証は `Authorization: Bearer` ヘッダと `X-Impersonate-User-Name` で行う。
  - ブラウザの `EventSource` はヘッダを付けられないので、フロントのサーバー（React Router）が中継する予定。そのため、ヘッダで認証できればよい（クエリにトークンを載せる方式は要らない）。
- 再接続したときに取りこぼさないよう、イベントの `id` に `message_uuid` を入れ、`Last-Event-ID` ヘッダ（または `?after=`）より後のメッセージから送り直してほしい。
- イベント種別（案）：
  - `message`：新しいメッセージ（data は logs API の 1 件と同じ JSON）
  - `season`：シーズンが切り替わった（data は新しいシーズン。例 `{"season": "1901f"}`）。フロントはこれを受けて現在のシーズンを読み直す。
- 接続を保つためのコメント行（`: ping`）を定期的に送ってほしい（プロキシのタイムアウト対策）。

## 4. チャンネルごとの未読数・最終既読【任意・後回しでよい】

チャンネル一覧に未読数を出したくなったときに相談する。今は不要。

## 将来：チャンネルをサーバーで持つ【今は不要】

今はメンバーの組み合わせをそのままチャンネルとして扱っている。次のようなことが必要になったら、チャンネルの API（一覧・作成・メンバー）を相談したい。

- 発言する前に、空のチャンネルを作って一覧に出したい
- チャンネルに名前を付けたい
- 同じメンバーで複数のチャンネルを作りたい

---

## 相談したいこと

1. 開戦前夜・感想戦で発言できるのは誰か（参加者だけか。感想戦は第三者も書けるか）。また、この時期に密談や独り言を書けるか。
2. 感想戦の間（Finished / Solo / Draw）と終わった卓（Closed / Aborted）で、独り言も全員に公開してよいか。今の logs API は `in_progress` 以外なら全員に全メッセージを返している。
3. 管理人発言を、`kind: "public"` に `sender_kind: "admin"` を付けて表すか、新しい `kind`（例 `"admin"`）にするか。フロントはどちらでも対応できる。
