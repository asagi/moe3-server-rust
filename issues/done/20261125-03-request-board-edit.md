# 盤面編集（ユニット配置・占領情報）の API 変更の依頼

フロント（moe3-front-rr）に、卓の現在のフェイズのユニット配置と占領情報を編集する画面（タブバーの歯車アイコン）を作る。既存の次の 4 本の API を使うつもりで、使う人・使えるフェイズなどを広げてほしい。

- `PUT /admin/games/:game_uuid/units/:location`
- `DELETE /admin/games/:game_uuid/units/:location`
- `PUT /admin/games/:game_uuid/territories/:code`
- `DELETE /admin/games/:game_uuid/territories/:code`

あわせて、編集画面に出す今の盤面を取る API と、滅亡の判定の変更もお願いしたい。

項目ごとに「必須」「任意」を付けた。エンドポイント名やフィールド名は案なので、サーバー側の命名規則に合わせて変えてよい。

---

## 前提（フロント側で決まっている仕様）

- 使えるのは、**卓主**と**管理者モード中の管理者**だけ。
  - 管理者モードはフロントのセッションにだけある状態で、サーバーは知らない。サーバーは「卓主か、`is_admin` のアカウントか」だけを見ればよい。管理者モードかどうかはフロントが絞る。
  - `X-Impersonate-User-Name` 付きのリクエストは、切り替え先のアカウントとして判定する（切り替え先が卓主なら使える）。
- 使えるフェイズは、**開戦前夜**と**メインフェイズ（春・秋）**。撤退フェイズ・調整フェイズ・感想戦では使えない。終わった卓（Closed・Aborted）でも使えない。
- 編集できるのは**最新フェイズだけ**。
- 開戦前夜に、ある国の占領地とユニットをすべて消すと、その国は滅亡した状態で始まる。その国も通常どおり担当者に割り当ててよい（通常のプレイでは起きない状況なので、特別扱いはしない）。
- 占領情報は、補給都市でない陸地も対象（地図の色分けに使っているため）。今の API と同じく、海は対象外。
- 単独勝利の判定は、今までどおり占領判定のとき（秋の撤退フェイズの終わり）でよい。編集した直後には判定しない。

---

## 1. 卓主に加えて管理者も使えるようにする【必須】

4 本とも、今は卓主でないと `403 forbidden`（`user is not the owner of this game`）になる。**`is_admin` のアカウントも使えるように**してほしい。

## 2. 開戦前夜でも使えるようにする【必須】

4 本とも、今はメインフェイズ（`SpringMain` / `FallMain`）でしか使えない。**開戦前夜（`Ready`）でも使えるように**してほしい。

- `season` は今 `<年4桁><s|f>` の形だけを受け付けている。開戦前夜は `"ready"` を受け付けてほしい（`current_turn()` と同じ値）。
- 開戦前夜のフェイズに置いたユニットには、命令を作らなくてよい（1901 年春のメインフェイズを作るときに、`init_main_phase_orders` で維持命令が作られるため）。
- 開戦前夜に編集したユニットと占領地が、1901 年春に引き継がれることをテストで確かめてほしい（`initialize` で前のフェイズからコピーしているので、今のままで引き継がれるはず）。

## 3. ユニットを消したときの命令【確認・ドキュメント】

`set_unit` を読んだところ、DELETE でもそのユニットの命令を消していた。これは仕様どおり。

- `admin-games-units__delete.md` には命令を消すことが書かれていないので、ビジネスルールに追記してほしい。
- **消したユニット自身の命令は必ず消す**【必須】。支援・輸送は仮想命令の考え方で解決しているので、消したユニットの移動命令などが残っていると、それを支援・輸送する他国の命令が成功してしまう。消したユニット自身の命令が残らないことを、テストで確かめてほしい。
- 消したユニットを支援・輸送していた**ほかのユニットの命令**は、考えなくてよい。一致する命令がなければ、解決時に失敗として処理されるため。

## 4. 今の盤面を取る API【必須】

編集画面に、最新フェイズのユニット配置と占領情報を出したい。今の結果取得 API（`/result/:season`）は開戦前夜を扱わないので、別の API がほしい。

### エンドポイント（案）

- `GET /games/:game_uuid/board`
- 認証不要（ユニット配置と占領情報は、誰でも見られる情報なので）

### レスポンス（案）

```json
{
  "season": "1901s",
  "phase_kind": "main",
  "units": [{ "power": "f", "kind": "a", "location": "par" }],
  "territories": [{ "power": "f", "code": "par" }]
}
```

| フィールド    | 説明                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------- |
| `season`      | 最新フェイズのシーズン（`current_turn()` と同じ形）                                           |
| `phase_kind`  | 最新フェイズの種別（`GET /games/:game_uuid` の `phase_kind` と同じ値）                         |
| `units`       | 最新フェイズのユニット。`location` は PUT/DELETE のパスに使う地域コードと同じ形（`spa_nc` など） |
| `territories` | 最新フェイズの占領情報（補給都市でない陸地を含む）                                            |

- 命令は含めない（進行中は他国の命令が見えてはいけないため）。

## 5. 滅亡の判定を変える【必須】

今の `is_power_eliminated` は、最新フェイズに**ユニットが 1 つもない**国を滅亡とみなしている。これを、**ユニットと補給都市がどちらもゼロ**の国を滅亡とみなすように変えてほしい。

- ユニットが残っていれば、補給都市を占領して復活できる。補給都市が残っていれば、調整フェイズでユニットを作れる。どちらかが残っているあいだは滅亡ではない。
- 補給都市でない陸地の占領は、判定に含めない。
- この判定は、次の 3 か所で使われている。3 か所とも新しい判定になってほしい。
  - 発言 API の Ghost 発言への切り替えと、密談の拒否
  - 卓情報 API の `players[].is_eliminated`
  - SSE とログ取得 API（今は滅亡の判定を使っていないはず。使っていたら同じく）
- 開戦前夜と感想戦は、今までどおり滅亡とみなさない。

## 6. テスト

次のテストを追加してほしい。

- 管理者（卓主でない）が 4 本の API を使える。卓主でも管理者でもないアカウントは `403` になる。
- 開戦前夜に `season: "ready"` で編集できる。撤退フェイズ・調整フェイズ・感想戦では `403` になる。
- 開戦前夜に編集したユニットと占領地が、1901 年春に引き継がれ、ユニットには維持命令が作られる。
- ユニットを DELETE したあと、そのユニット自身の命令が残っていない。
- 盤面取得 API が、開戦前夜とメインフェイズの盤面を返す。
- 滅亡の判定：ユニットがなく補給都市が残っている国は滅亡ではない。補給都市がなくユニットが残っている国も滅亡ではない。どちらもない国だけが滅亡。
