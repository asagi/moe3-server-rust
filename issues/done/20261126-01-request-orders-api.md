# 命令画面のための API の依頼

フロント（moe3-front-rr）に命令画面（`/games/:uuid/orders`）を作る。メイン・撤退・調整の各フェイズで参加者が命令を出す画面で、撤退・調整フェイズのあいだは参加者のメイン画面になる。第三者と過去のシーズンを見る人には、結果を見せる画面になる。

今のサーバーには、命令の取得・提出 API がない（`issues/20260506-09〜13` は中身が未決の下書きなので、この依頼で置き換える）。あわせて、国ごとの状況を返すことと、進行中の命令が見えてしまう問題の修正もお願いしたい。

項目ごとに「必須」「任意」を付けた。エンドポイント名やフィールド名は案なので、サーバー側の命名規則に合わせて変えてよい。

---

## 前提（フロント側で決まっている仕様）

- 命令は、参加者がブラウザの中で編集し、「更新」ボタンで**まとめて確定**する。確定するまでサーバーには送らない。「キャンセル」はブラウザの中の変更を捨てるだけ。
  - そのため、命令ごとの PUT / POST / DELETE（下書き 11〜13）は要らない。**1 本の PUT で、その人の命令を丸ごと置き換える**形にしてほしい。
- メインフェイズでは、自国ユニットへの命令に加えて、**他国の全ユニットへの仮定命令**を出せる。仮定命令は本人にしか見せない（`/result` が `is_assumed()` を除いているのと同じ考え方）。フェイズが変われば引き継がない。
- **移動先などの候補はサーバーが作る**。フロントには隣接情報を持たせない。
  - 移動は**陸路と海路を区別**する。
  - 海路移動の候補は、「その時点で盤面にあるすべての海軍が輸送に同意した場合に、たどり着ける海岸すべて」。内陸にいる陸軍には、海路移動の候補自体を出さない。
- 和平合意は、今の卓主だけのフラグ（`PUT /admin/games/:uuid/draw-proposal`）のままでよい。
- 無政府状態の判定は、今のサーバーの判定（`last_access_at` と `idle_limit_minutes`）をそのまま使う。
- 視点変更（`X-Impersonate-User-Name`）中は、切り替え先のアカウントの権限をそのまま使う。切り替え先が参加者なら、その人として命令を取得・確定できる。
- 定時更新の卓では、即時進行のトグルを出さない。操作が要らない国には、命令欄を出さない。
- 和平合意のトグルは命令画面に置かず、卓主の操作（次回更新時刻の変更と同じところ）に入れる。細かい仕様は別途相談するので、この依頼では扱わない。

---

## 1. 進行中のフェイズの命令を `/result` で返さない【必須・不具合】

`GET /games/:uuid/result/:season` は認証不要なのに、**進行中（`status: "open"`）のフェイズの命令もそのまま返している**。メインフェイズ中に呼ぶと、全国の自軍命令が誰にでも見えてしまう。

- 最新フェイズ（`open`）の `orders` は、空の配列で返してほしい（`status: "open"` はそのまま）。
  - 撤退・調整フェイズが進行中のときも同じ（撤退先や増設先が事前に見えるのは困る）。
- 自分の命令は、下の 2 の API で取る。

## 2. 自分の命令と候補の取得【必須】

### エンドポイント（案）

- `GET /games/:game_uuid/orders`
- 認証必須。担当国のある参加者だけ（そうでなければ `403`）。
- 最新フェイズがメイン・撤退・調整のときだけ使える（開戦前夜・感想戦・終わった卓は `403`）。

### レスポンス（案）

```json
{
  "season": "1901s",
  "phase_kind": "main",
  "power": "f",
  "needs_action": true,
  "orders": [
    { "unit_power": "f", "unit_kind": "a", "location": "par", "order_kind": "move", "dest": "bur", "via_convoy": false },
    { "unit_power": "g", "unit_kind": "a", "location": "mun", "order_kind": "move", "dest": "bur", "via_convoy": false }
  ],
  "options": [
    {
      "unit_power": "f",
      "unit_kind": "a",
      "location": "bre",
      "move_dests": ["par", "pic", "gas"],
      "convoy_dests": ["lon", "wal", "bel", "spa", "por", "naf"],
      "support_targets": [
        { "target_location": "par", "target_dests": [null, "pic", "gas"] }
      ],
      "convoy_targets": []
    }
  ],
  "adjustment": null
}
```

- 地域コードは、`GET /board` と同じ形（小文字、海岸は `spa_nc` など）にしてほしい。`/result` は `Lon` のような短縮名なので、そろえてもらえると助かる（`/result` を変えるのは任意）。
- `power`：その人の担当国。
- `needs_action`：このフェイズで操作が必要か（`progress-consensus` の「操作が必要な勢力」と同じ判定）。`false` なら、フロントは命令欄を出さずに「ほかの人を待ってね」と出す。

### `orders`

その人が今出している命令。自国ユニットへの命令と、その人の仮定命令（メインフェイズだけ）。

- `unit_power`：命令の対象ユニットの国。担当国と違えば仮定命令。
- 残りのフィールドは `/result` の `OrderEntry` と同じ（`status` は要らない）。
- 自国ユニットには、今までどおりサーバーが初期値を入れておく（メイン：維持、撤退：解体、調整：解体が必要な国は自動で選んだ解体）。
- 仮定命令を出していない他国ユニットは、`orders` に含めなくてよい。フロントは「維持」として表示する。

### `options`

命令を出せるユニットごとの候補。メインフェイズでは盤面の全ユニット（仮定命令のため）、撤退フェイズでは自国の撃退されたユニットだけ。

| フィールド        | フェイズ | 説明                                                                                         |
| ----------------- | -------- | -------------------------------------------------------------------------------------------- |
| `move_dests`      | メイン   | 陸路（海軍は海路）で移動できる地域                                                           |
| `convoy_dests`    | メイン   | 海路移動できる海岸（上の前提どおり）。海軍と内陸の陸軍は空配列                               |
| `support_targets` | メイン   | 支援できるユニットと、その支援先。`target_dests` の `null` は維持の支援                      |
| `convoy_targets`  | メイン   | 輸送できる陸軍と、その移動先（`[{ "target_location": "lon", "target_dests": ["bel"] }]`）。海にいる海軍だけ |
| `retreat_dests`   | 撤退     | 撤退できる地域（攻撃元・スタンドオフ・ほかのユニットがいる地域を除く）                       |

- 支援の候補は、「支援するユニットが移動できる地域」と「支援されるユニットの移動先（海路を含む）」が重なるものになるはず。
- 輸送の候補は、`convoy_dests` と同じく「すべての海軍が輸送に同意した場合」の経路で、その海軍を通るもの。

### `adjustment`（調整フェイズだけ。ほかは `null`）

```json
{
  "build_count": 2,
  "disband_count": 0,
  "buildable": [
    { "location": "par", "unit_kinds": ["a"] },
    { "location": "bre", "unit_kinds": ["a", "f"] },
    { "location": "stp_nc", "unit_kinds": ["f"] }
  ]
}
```

- `build_count`：増設できる最大数（デザインの「n/m」の m）。
- `disband_count`：解体しなければならない数。解体は自国ユニットならどれでも選べるので、候補は要らない。
- `buildable`：今空いている本国の補給都市と、置けるユニットの種類。海岸が複数ある地域は、海岸ごとに分けてほしい。

## 3. 命令の確定【必須】

### エンドポイント（案）

- `PUT /games/:game_uuid/orders`
- 認証・使える人・使えるフェイズは 2 と同じ。`needs_action` が `false` の国は `403`。

### リクエスト（案）

```json
{
  "season": "1901s",
  "phase_kind": "main",
  "orders": [
    { "unit_power": "f", "unit_kind": "a", "location": "par", "order_kind": "move", "dest": "bur", "via_convoy": false },
    { "unit_power": "g", "unit_kind": "a", "location": "mun", "order_kind": "hold" }
  ]
}
```

- `season` と `phase_kind` は、フロントが見ていたフェイズ。最新フェイズと違えば `409`（フェイズが進んだあとに古い画面から確定するのを防ぐ）。
- **その人の命令を丸ごと置き換える**。
  - 自国ユニットのうち、含まれていないもの：メインは維持、撤退は解体にする。
  - 仮定命令は、含まれていないものを消す（維持扱い）。
  - 調整フェイズ：増設は `build_count` 以下、解体はちょうど `disband_count` 個。足りなければ `400`（フロントは解体を「差し替え」でしか変えられないようにするので、数が合わないのはおかしなリクエストだけのはず）。
- 候補（2 の `options` / `adjustment`）にない命令が 1 つでもあれば、何も変えずに `400`。どの命令がだめだったか分かるようにしてほしい（例：`{"code":"invalid_order","message":"...","location":"par"}`）。
- 成功したら、2 と同じ形のレスポンスを返してほしい（確定後の状態をフロントが表示し直すため）。
- `game_update_lock` を取って、定時進行とぶつからないようにしてほしい。

## 4. 国ごとの状況【必須】

画面の下に、7 か国の状況表（補給都市・陸軍・海軍・即時進行、無政府なら赤、滅亡ならグレー）を出す。第三者にも同じ表を見せる。今の `GET /games/:uuid` の `players[]` には数も無政府もないので、足してほしい。

### 案：`GET /games/:game_uuid/board` に `powers` を足す

```json
{
  "season": "1901s",
  "phase_kind": "main",
  "units": [...],
  "territories": [...],
  "powers": [
    {
      "power": "f",
      "supply_centers": 3,
      "armies": 2,
      "fleets": 1,
      "needs_action": true,
      "progress_consented": false,
      "is_idle": false,
      "is_eliminated": false
    }
  ]
}
```

| フィールド           | 説明                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| `supply_centers`     | 占領している補給都市の数                                                                                 |
| `armies` / `fleets`  | ユニットの数。撤退フェイズでは撃退されたユニットも数える                                                 |
| `needs_action`       | このフェイズで操作が必要か（2 と同じ判定）                                                               |
| `progress_consented` | 即時進行に合意しているか（`players[].progress_consented`）                                               |
| `is_idle`            | 無政府状態か（`is_idle_or_missing` の判定）。担当者がいない国も `true`                                   |
| `is_eliminated`      | 滅亡しているか（`players[].is_eliminated` と同じ判定）                                                   |

- 和平合意は卓主だけの権限なので、状況表には出さない。`powers` にも入れなくてよい。
- 置き場所は `GET /games/:uuid` の `players[]` でもよい。どちらにするかはサーバー側で決めてよい。

## 5. 撤退フェイズの盤面【必須】

撤退フェイズの地図には、撃退された自軍ユニットを半透明にして × を重ね、攻めてきた敵ユニットは移動前の位置に描く。そのため `GET /board` の `units` に次を足してほしい。

- `dislodged`（`boolean`）：撃退されたユニットか。
- `dislodged_from`（`string | null`）：攻撃元の地域。海路で攻められたときは `null`（`Unit` の今の値どおり）。

攻めてきたユニットが元はどこにいたかは、フロントが `/result` のメインフェイズの命令（成功した移動）から求める。

## 6. 過去のシーズンの状況表【必須】

過去のシーズンを見るときも、状況表を出す。そのシーズンの最後のフェイズの数が要る。

- `GET /games/:game_uuid/board?season=1901s` のように、シーズンを指定できるようにしてほしい（指定がなければ最新フェイズ）。返すのは、そのシーズンの最後のフェイズの `units`・`territories`・`powers`。
- 過去のシーズンの `progress_consented` と `is_idle` は残っていないはずなので、`null` でよい（フロントは「—」を出す）。

## 7. 状況表の更新を SSE で知らせる【任意】

ほかの人が即時進行に合意したり、命令を確定したりしたら、状況表を更新したい。

- 即時進行はシステムメッセージが流れるので、それを合図にフロントが読み直すこともできる。
- できれば SSE（`/messages/stream`）に `board` のようなイベントを足し、状況が変わったら送ってほしい（中身は空でよい。フロントが `GET /board` を読み直す）。
- 命令の確定は、他国に知らせない（中身はもちろん、確定したかどうかも見せない）。

## 8. テスト

- `/result`：進行中のフェイズの `orders` が空になる。終わったフェイズは今までどおり返る。
- `GET /orders`：自国の命令と自分の仮定命令だけが返る。他国の命令・他人の仮定命令は返らない。参加者でなければ `403`。
- 候補：
  - 内陸の陸軍には `convoy_dests` が空。
  - 海軍が 1 隻もなければ、どの陸軍の `convoy_dests` も空。
  - 海軍が連なっていれば、その先の海岸が `convoy_dests` に入る。
  - 撤退先から、攻撃元・スタンドオフ・ほかのユニットがいる地域が除かれる。
  - 海岸が複数ある地域は、海岸ごとに分かれる。
- `PUT /orders`：
  - 丸ごと置き換わる。含まれていない自国ユニットはメインなら維持、撤退なら解体になる。
  - 候補にない命令があると何も変わらずに `400`。
  - フェイズが違うと `409`。
  - 調整：増設が多すぎる、解体の数が合わないと `400`。
  - 視点変更中は切り替え先として扱われる。
- `GET /board`：`powers` の数、撤退フェイズの `dislodged` / `dislodged_from`、`?season=` で過去のシーズンが返る。
